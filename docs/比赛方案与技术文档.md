## 1. 比赛概述

### 1.1 规则要点
- **时长**：现场测试 5 分钟，超时项目不计分。**总成绩 = 焊接 20% + 现场测试 60% + 技术报告 20%**
- **技术报告截止**：8/12 14:00，提交链接 `https://jsj.top/f/e0Pm18` —— 20% 总分，绝不能漏！
- **得分项**：Ⅰ区完成 5 / Ⅱ区完成 10 / Ⅲ区完成 5 / Ⅳ区完成 10；各区敌军友军数量报告 20（每区 5）；击倒各区敌军 40（每区 10）；雷区排雷数量报告 10（每区 5）
- **扣分项**：碰撞场地 2/次；触碰反坦克雷 5/次（上不封顶）；击倒友军/人质 10/次（上不封顶）
- **判负**：车体四轮完全进入雷区 = 直接判负
- **总数已知**：敌军 6（每区 1-2）、人质 3、友军 7；地雷红蓝各 10，雷区 Ⅱ/Ⅲ 各 1 盘（红=未排雷、蓝=已排雷）；反坦克盘 1 个（Ⅳ 区，位置固定但现场裁判决定，直径 ~10cm 圆形贴盘）

### 1.2 必须逐字输出的 6 行串
```
A区发现x个敌军、x个友军和X个人质     ← 注意：全角顿号"、"、"和"连接；A/B/C/D
B区发现x个敌军、x个友军和X个人质
C区发现x个敌军、x个友军和X个人质
D区发现x个敌军、x个友军和X个人质
A雷区未排雷数量x个,已经排雷数量x个   ← 注意：此处是**半角逗号**"，"
B雷区未排雷数量x个,已经排雷数量x个
```
- 同时必须**保存带标注框的图片**（框 + 类别 + 置信度）

### 1.3 器材与约束
- **底盘**：麦克纳姆轮全向（odom_model_type="omni"，`/dev/carserial`→ttyUSB0 @115200，协议 AA BB 0A 12）
- **激光**：Lslidar N10_P 2D @460800，前向 180°，装高 5cm，对低矮贴盘**不可见**（反坦克盘激光看不见）
- **云台**：舵机 pan 0-180（中心 90）、tilt 70-110（中心 90），水弹枪 `/dev/gun`→ttyUSB2 @115200（AA BB 01/02 角度、AA BB 03 01/00 开火，**0.05s 短促有效**，冷却 1s）
- **webcam**（`/dev/video0`）：**只支持 MJPG**，**848×480 稳定，640×480 会失败**；装在云台上随舵机转
- **Orbbec DaBai DCW2**：只能走官方 SDK（UVC 无效），RGB 640×480 + depth 640×400，深度 0-1m 有效，装车头固定
- **模型**（都 640 输入，CPU onnxruntime，**分开训练**）：
  - `person.onnx` = {0:hostage, 1:enemy, 2:friend}（**必须重训，现有的是 2 类错误模型**）
  - `mine.onnx` = {0:mine_red, 1:mine_blue}
  - `anti_tank.onnx` = {0:anti_tank}
  - `fire.onnx` **废弃不用**（target 类在比赛中不存在，打靶目标就是 enemy）

## 3. 子系统 A：webcam 云台 —— 人物计数 + 打靶

核心：webcam 和枪共享云台，**"识别"和"打靶"合并为一次云台扫描**，扫描同时得到计数和每个敌人的**绝对瞄准角**。

### 3.1 每个区流程（≤20s）
1. **归位**：servo1→90、servo2→T0（标定值 78-82）；等稳定
2. **计数扫描**（开枪前锁数量，打倒的敌人仍算"发现"）：
   - tilt 两档 × pan 5 位（90±40，步进 25°，夹 [5,175]）
   - 每位置：写舵机→停 0.40s→取 1 帧（置信 0.45-0.60 补第 2 帧确认）
   - person.onnx 逐帧推理，把检测映射到**绝对云台角**：
     ```
     abs_pan  = pan_cmd  + s_h * (u - W/2) / ppd_h
     abs_tilt = tilt_cmd + s_v * (v - H/2) / ppd_v
     ```
   - 2 档 × 5 位 × ~0.55s ≈ **5.5s**
3. **聚类去重**：同类别，|Δpan|<5° 且 |Δtilt|<8° 归同一人；tilt 级重复 3° 合并；类别冲突（6° pan 内异类）取高置信；跨度>8°→微扫拆
4. **立即上报**（先把分拿到）：`"A区发现2个敌军、1个友军和0个人质"`；敌人数必须 1-2（规则），异常补扫一次
5. **打靶**（按绝对角逐个打 enemy）：
   - aim：servo1→abs_pan，servo2→abs_tilt + TILT_OFFSET(d)（**垂直补偿，按距离查参数表**）
   - **开火前安全门**：±6° pan 内必须 enemy conf≥0.50；若友军/人质 conf≥0.70 在 6°pan×10°tilt 内→重扫/跳过（宁丢 +10 不赌 -20）
   - 闭环微调 ±1-2°，直到目标居帧心 3% 内
   - 开火 0.05s burst，冷却 1.0s（车停 + 舵机稳定才打）
   - **击倒验证**：重瞄准（换新位姿）后应无 enemy（conf<0.40）或框高比下降；最多重试 2 次
6. **证据图**：每簇存 1 张标注图（框+类别+置信度+绝对角），文件名如 `R_A_enemy_conf0.83_pan075.jpg`
7. 云台归位，通知 nav 下一目标

### 3.2 标定（8/9 场地前完成，存 params.yaml）
- `ppd_h / ppd_v`：云台每度的像素数（尺子/已知角度实测，含舵机非线性）
- `s_h / s_v`：正负号因子（+pan 目标往哪边移）
- `T0`：各区的俯仰基准
- `TILT_OFFSET(d) = a0 + a1/d`：水弹道落点 vs 相机中心（0.8/1.5/2.0m 实测；旧 `-3.8` 是水平常量**不可复用**）
- 距离 d 由框高反推：`d = (贴纸高度m × 焦距) / 框高px`

## 4. 子系统 B：Orbbec —— 雷区计数 + 反坦克盘

### 4.1 雷区流程（每区 ≤10s）
- nav 发 `/mine_detect "A"`，底盘做 ±8° rotate-goal 小转扫视（cmd_vel 归 move_base）
- mine.onnx 逐帧记录（类别、bbox 中心、深度）
- **去重**：图像空间 IoU 跨帧为主，地面投影为辅（不依赖深度洞）
- 每区最多 1 盘（红=未排雷、蓝=已排雷，同盘双色取高置信；两区红蓝总数==2 做 sanity）
- 上报 `"A雷区未排雷数量x个,已经排雷数量x个"`（半角逗号）
- 6s 无检测→补扫一次；仍空→报 0,0 + 存原始帧

### 4.2 反坦克盘（Ⅳ 区走廊，深度路径）
> ⚠️ **已被 §5 子系统 C 取代**（比赛用 §5 的常驻避障节点 + global+local 双注入）；本节仅保留作参考。
1. **门控**：仅当 nav 处于 C→D 走廊段时启用 anti_tank.onnx（用 nav 状态门控，不用裸 odom 阈值）
2. **确认**：连续 2 帧 + 深度一致（ΔD<0.15m）或单目框宽反推（D = 0.10m×focal/框宽，±20%）
3. **注入**：发布 `/vision/obstacle_cloud`（半径 0.05m 点云，z=0，odom 系）→ **local costmap 视觉障碍层**（规则推荐的"深度→点云→costmap"做法）
4. **避让**（nav 层主路径）：取消当前目标 → 发走廊内 [0.20,0.80] 横向中间目标（选空间大侧）→ 恢复原目标
5. **硬停兜底**：盘心<0.30m 或 4 角<0.05m → 零速 + 后退 0.20m
6. **过盘后停止发布云**（陈旧云不能堵回程路）；若始终过不去：停安全位、清空云、弃绕行但**绝不碰盘**
7. 保存标注图（框+置信度+实测 D）

### 4.3 costmap/planner 关键参数（写入本包 param/）
- `vision_obstacle` **只进 local costmap**（global 会残留堵回程）；marking:true / clearing:false
- inflation_radius 0.06、cost_scaling_factor 8.0
- DWA：`vy_samples:20`（Mecanum 横移必需）、Ⅳ 区 max_vel_x 0.10 m/s（正常 0.20）
- footprint 0.35×0.30m 保持不变

## 5. 子系统 C：视觉避障（雷区盘 + 反坦克盘连续避障，8/10 新增）

移植自 `visual_mine_avoidance_github`，适配本机（ROS Melodic / py3 无 tf2_ros / costmap 约束）。**取代 §4.2/4.3 旧的 `vision_obstacle` 单发点云方案** —— 旧的只发一次、只进 local、无清除，会残留堵回程；本方案连续重发 + observation_persistence 到期自然消失，且 global+local 双注入。

### 5.1 原理（关键裁决）
- **点云发在传感器帧 `camera_color_optical_frame` + 球面点集**，节点内**零动态 TF**（py3 下 `tf2_ros`/`tf.transformations` 均不可用，绝不 import），由 **costmap_2d C++ tf2** 变换到 odom/map —— 与 laser_link 的 scan 完全同构的标准模式。
- **球面点集**（Fibonacci，每盘 20 点，半径 mine 0.12m / anti_tank 0.15m）：任一姿态下 XY 投影≈半径 R 圆盘，免疫车俯仰/roll。
- **每类独立 MineTracker** 时序确认（min_hits=2 确认 / max_miss=8 丢弃 / 指数平滑 / stale 2s 清候选；confirmed 只由 max_miss 清除），静态盘对车移动鲁棒。

### 5.2 链路
```
Orbbec (dabai_dcw2.launch, enable_depth:=true) 
  /camera/color/image_raw (640x480) + /camera/depth/image_raw (640x400 16UC1 毫米) + info
    → visual_mine_avoidance.py (yolov8 py3 env)
    → 每 tick: mine.onnx; 每 3 tick: anti_tank.onnx
    → bbox 底边中点 → 3x3 中值深度 (depth y 按 400/480 缩放) → 光学系 (X,Y,Z)
    → 每类 MineTracker 确认
    → /visual_mine/obstacles (PointCloud2, camera_color_optical_frame, 球面点集)
    → costmap_2d 注入 obstacle_layer (visual_mine 源) → 规划器自动绕行
```

### 5.3 costmap 注入机制（重要）
- `nav_competition_2026.launch` **自持一份 move_base**（`clear_params="true"`，无 ns），在 `<node>` 内按序 rosparam load：
  1) robot_bringup 的 7 个参数文件（costmap_common ×2 + local/global costmap + move_base + global_planner + dwa）
  2) **最后** load `param/visual_layer_params.yaml`，分别 `ns="global_costmap"` 与 `ns="local_costmap"`，覆写 `observation_sources: "scan visual_mine"` + 新增 `visual_mine` 源块
- roslaunch 在 spawn move_base 前把节点内全部 rosparam 写入参数服务器 → 确定性生效，绕开 robot_bringup / robot_navigation 等底层包 + `clear_params` 清参数的坑。
- `visual_mine` 源：`marking:true / clearing:false / max_obstacle_height:0.4 / obstacle_range:3.0 / raytrace_range:3.5 / observation_persistence:2.0`。盘移走后 2s 自然消失（不堵回程，验证过 obstacle_layer 先清本层再按 buffer 重标记）。

### 5.4 实测量化（本机 4 核）
- `mine.onnx` 640×480 单次推理 ≈0.20s（intra_op_num_threads=2，4 线程仅快 5%，不值）→ 实测 cloud ≈4Hz（理论 10Hz 上限，受 CPU 封顶）。
- **可接受**：盘是静态的，tracker 持续确认 + costmap `observation_persistence=2.0` 保证 obstacle 层连续标记；点云每帧按当前位姿重变换，无陈旧位置风险。
- 想提速先调 `~at_infer_interval`（反坦克盘只在 Ⅳ 走廊，可调大）与 `~intra_op_num_threads`。

### 5.5 相机与 TF
- orbbec 必须 `enable_depth:=true`（`orbbec_mine_antitank.py` 的自动拉起已改；比赛由 nav launch 顶层起 driver，任一方先拉都带深度，消除双拉冲突）。
- TF 链：`map→odom(AMCL)→base_footprint(EKF)→base_link(恒等)→camera_link(本包静态TF, cam_*)→camera_color_frame→camera_color_optical_frame(驱动)`。
- 节点回退：camera_info 5s 无 → 默认内参 fx/fy/cx/cy=610/610/320/240；depth 无/未知编码 → 无 3D 点不崩；模型缺失 → **logfatal + exit(1)**（不带病运行）。

### 5.6 启动 / 验证
```bash
roslaunch raicom2026 nav_competition_2026.launch use_rviz:=false   # 比赛
roslaunch raicom2026 visual_mine_avoidance.launch use_rviz:=true   # bench 只测避障

rosrun tf tf_echo base_link camera_link                       # 有输出
rostopic hz /visual_mine/obstacles                            # ≈4-5Hz（CPU 封顶）
```
bench 标定：车静止，贴纸/真盘放相机前 0.4~0.9m，RViz Fixed=base_footprint 看 `/visual_mine/markers` 是否压贴纸；偏移改 `nav_competition_2026.launch`/`visual_mine_avoidance.launch` 的 `cam_*` 直至重合；云中心 vs 真值水平误差 <0.15m。

## 6. 避障与应急（TIER 降级链）

| TIER | 故障 | 动作 |
|---|---|---|
| 0 | 全正常 | 满分路径（报告 80 + 击倒 40 + 雷区 10 + 反坦克 0 损失） |
| 1 | Orbbec 死（3s 无帧/USB 12M） | 赛前：蜂鸣+物理重插 <30s；赛中：雷区用 webcam 地面扫（tilt 70-78）；反坦克→单目框宽反推；Ⅳ 前无 Orbbec 则入口硬停 + webcam 扫盘，0.06 m/s 慢过，模糊则弃过（丢 D 交通，不判负） |

| 3 | 云台串口死 | 底盘小 yaw（±8°）补视角计数，打靶不可能（丢 40） |
| 4 | 双相机全死 | 保导航继续走（控制碰撞扣分），全部报空，**不进 Ⅳ** |

## 9. 已知风险与对策（对抗验证结论）

1. **person.onnx 现有模型是 2 类/480** → 必须重训 3 类 {hostage,enemy,friend}，现场数据含斜视/压缩裁剪；旧模型绝不能用于比赛
2. **打靶垂直补偿**：旧 `-3.8` 是水平常量，加到俯仰轴会系统性脱靶 → 用新标定的 `TILT_OFFSET(d)=a0+a1/d`
3. **反坦克居中时 1m 走廊几何**：初版参数无通过带 → cluster 0.05m + inflation 0.05-0.06 + 中间目标夹 [0.20,0.80] + 速度 0.10
4. **技术报告 20%**：8/12 14:00 硬截止，8/8-10 起草、8/11 定稿、8/12 上午提交，专人负责
5. **AMCL 初始位姿**：8/10 记录起点，硬写 initial_pose_x/y/yaw，避免 (0,0,0) 不收敛
6. **webcam 640×480 失败**：一律 848×480 MJPG，代码里禁止请求 640×480
