> 时间假设：技术报告 8/12 已交；比赛现场测试日期待定。本计划按"剩余 2 个上机日"
> 倒排，比赛日不同则等比例压缩/扩展。
> **总原则：先跑通基础，再逐任务叠加；每阶段有明确验证标准；绝不在未验证的代码上叠新功能。**

> 任务二（雷区）纯识别计数无标定依赖 → 第二；任务一（打靶）依赖全套标定 → 最后。

## 阶段 1：环境检查 + 建图

**目标**：获得比赛同款地图的精确栅格地图（这是后面一切的基础）。

**动作**：
1. 硬件检查：`ls /dev/ttyUSB*`、`/dev/lslidar`、`/dev/gun`、`/dev/video0` 齐全；`lsusb -t` 确认 Orbbec 480M（12M 则物理重插）
2. 相机检查：`roslaunch raicom2026 detect.launch` 后 `rostopic hz /usb_cam/image_raw`（应 ~30Hz）与 orbbec 帧率
3. 建图：`roslaunch raicom2026 test/launch 内建图 launch（已归档）` + `rosrun raicom2026 teleop_keyboard.py`
   - 慢速（倍率 ≤1.0）绕场一周，每条边进雷达视野（<6m），回到起点附近触发回环
   - 若日志 `constraint_builder_2d: M=0`（无回环）→ 调 `config/cartographer/my_car.lua`（min_score 0.5~0.55 优先）
4. 保存：`rosrun raicom2026 save_map.sh` → `data/maps/competition_map.pgm/.yaml`

**验证**：RViz 地图边界闭合、无重影双墙；yaml `resolution: 0.05`；雷区/四区位置能对上真实坐标。

**产出**：`competition_map.pgm/.yaml`（正式比赛用图）。

## 阶段 2：航点测量与配置

**目标**：8 个航点 + 起点初始位姿全部实测。

**动作**（在新图 competition_map 上）：
1. 启动 `nav_competition_2026.launch`，RViz 用 2D Nav Goal 逐站把车开到任务点
2. 记录每站 `map` 系坐标与车头朝向（识别点朝向=云台对目标方向；雷区点朝向=视场覆盖方向；IV 站取四区通道中点）
3. 填写 `param/nav_competition.yaml`：A/B/MineA/C/D/MineB/IV/END 共 8 站 + `amcl_initial_pose`（实测起点）
4. 校验：`--print-course` 无 (0.00, 0.00)

**验证**：`rostopic echo /nav_competition/state` 逐站手动发布目标验证可达（先单独 `rostopic pub /move_base_simple/goal` 测 1~2 站，再交给 nav 节点）。

**产出**：完整航点配置。

## 阶段 3：纯导航空跑全程

**目标**：先让车"会走路"，验证导航链路（AMCL 收敛、规划、避障、四区通过、回终点）。

**动作**：

2. 实车从营地出发，观察 `/nav_competition/state`：`BOOT→NAV:A_pos→…→NAV:IV_pos→NAV:END_pos→REPORT→DONE`
3. 全程录像，记录每站到达耗时与总用时；检查有无卡死/绕圈/贴墙

**验证**：8 站全到达（或按超时跳站后能继续）、回到终点、无碰撞。

**产出**：导航链路可用的基线；各段基准耗时。

## 阶段 4：任务三 —— 四区反坦克盘视觉避障（先做）

**目标**：四区反坦克盘能"看见 + 绕开"，门控生效。

**动作**：
1. 注入自检（每次启动必查）：
   ```bash
   rosparam get /move_base/local_costmap/observation_sources   # "scan visual_mine"
   rosparam get /move_base/global_costmap/observation_sources  # "scan visual_mine"
   rostopic hz /visual_mine/obstacles                          # 4~5Hz
   ```
2. bench 外参标定：车静止，贴纸放相机前 0.4~0.9m，RViz 看 `/visual_mine/markers` 红球压贴纸中心，偏移改 `nav_competition_2026.launch` 的 `cam_*` 参数
3. 实车四区测试：放反坦克盘模拟物 → 车通过时自动绕行；移走盘 → 2s 内点云消失不堵回程
4. 门控验证：`rostopic echo /nav_competition/zone`；避障节点日志仅在 `IV_pos` 显示"启用 anti_tank 推理"
5. （可选）降级验证：拔 Orbbec → TIER-1 降级日志

**验证**：注入自检 3 项全过；绕行不碰盘；门控切换日志正确。

**产出**：安全底线成立（不碰盘、不判负）。

## 阶段 5：任务二 —— 雷区识别（二区/三区）

**目标**：红蓝地雷识别 + 报告 + 证据图。

**动作**：
1. 确认 `mine.onnx` 可用（红/蓝两类）
2. 实车到二区：`rostopic pub -1 /mine_detect std_msgs/String "A"` → 5s 采样 → 检查 `/mine_detect_status` 与 `report_mine.txt`
3. 三区同理（"B"）
4. 放不同数量/颜色地雷组合，验证计数与去重（跨帧 IoU）
5. 验证"两区红蓝总数=2"的 sanity 逻辑（异常时提示）

**验证**：两区报告行字节级正确；证据图 `M_*.jpg` 存档。

**产出**：雷区任务分到手（10 分项）。

## 阶段 6：任务一 —— 人物识别 + 打靶（最后做，依赖标定）

**目标**：四点识别计数 + 有敌打靶 + 绝不误击。

**动作**（严格按顺序）：
1. **模型**：确认/重训 `person.onnx` 为 {hostage, enemy, friend} 三类（历史有 2 类错误版）
2. **标定**（`calibrate.py` + `param/params.yaml`）：
   - 相机内参（棋盘格 25~30 帧）
   - `ppd_h/ppd_v`（转已知角度量像素位移）
   - **`s_v` 方向（必做）**：tilt 90→100，目标 v 变大填 -1、变小填 +1（填反=永打不中）
   - 弹道 `a0/a1`（0.8/1.5/2.0m 三点拟合）
   - 全部完成验证后 `calibrated: true`（否则开火被锁）
3. **单点联调**：`rostopic pub -1 /person_detect std_msgs/String "A"` → 扫描 ~17s → 检查状态串、证据图、打靶行为
4. **四点逐个验证**：A/B/C/D 各放敌军/友军/人质组合：
   - 计数正确（数量、类别）
   - 有敌军 → 命中；无敌军 → 不开火
   - 友军/人质高置信度在场 → 跳过不射（安全校验生效）
5. 击倒验证：补射最多 2 次的逻辑

**验证**：四点识别报告正确；命中率记录；零误击。

**产出**：任务一分到手（识别 20 + 击倒 40）。

## 阶段 7：全流程整合演练

**目标**：5 分钟内完整跑完 8 站三任务，报告精确。

**动作**：
1. 恢复全部 tasks 配置，完整跑 3 遍（记录每遍成绩）
2. 每遍核对：6 行 `report.txt` 字节级精确（全角顿号/半角逗号）、证据图齐全（`data/evidence/`）
3. 记录：全程用时、识别正确点数、击倒敌军数、雷区报告正确性、有无碰撞/误击
4. 暴露的问题按"最小修改 + 回归单测"处理，改完重跑

**验证**：至少 1 遍全程成绩达到目标（用时 <5min、报告全对）。

**产出**：比赛成绩基线 + 技术报告实测数据。

## 风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| 建图回环失败 | 地图漂移 | 调 min_score 0.5~0.55；绕场两次；不行换 pbstream 高精度存档 |
| person 模型来不及重训 | 识别不准 | 先用现有模型 + 提高 conf 阈值（宁漏检不误检），打靶安全校验兜底 |
| 标定时间不够 | 打靶脱靶 | `calibrated: false` 锁开火，只拿识别分（20），不冒险扣分 |
| Orbbec 现场失效 | 避障失效 | TIER-1 降级：webcam 地面扫描 + 单目框宽反推 + 慢速通过 |
| 全程超时 | 丢分 | 全局预算 280s 自动跳站收尾；优化每站耗时（扫描参数） |
