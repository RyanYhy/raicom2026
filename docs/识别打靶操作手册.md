## 1. 链路总览

```
┌─ webcam_person_gun.py ─────────────────────────────────────────┐
│  /person_detect "A"~"D" 触发 → 云台两档俯仰×5位pan 扫描          │
│  → person.onnx → 绝对云台角 → 聚类去重 → 立即上报 + 证据图        │
│  → 对 enemy 瞄准/安全门/闭环微调/0.05s点射/击倒验证               │
│  输出: /person_detect_status + data/reports/report_person.txt   │
│        + data/evidence/R_*.jpg                                 │
└────────────────────────────────────────────────────────────────┘
┌─ orbbec_mine_antitank.py ──────────────────────────────────────┐
│  /mine_detect "A"/"B" 触发 → 5s 采样 mine.onnx → 跨帧去重       │
│  → 每区最多1盘(红蓝取高置信) → 上报 + 证据图 M_*.jpg            │
│  /antitank_check 触发 → anti_tank.onnx 连续2帧+测距一致确认       │
│  → /vision/anti_tank_event + 证据图 (+可选点云, 默认关)          │
│  输出: /mine_detect_status + data/reports/report_mine.txt       │
└────────────────────────────────────────────────────────────────┘
                最后: assemble_report.py → report.txt (恰好 6 行)
```

- 相机：webcam 848×480 MJPG（云台上）；Orbbec 走 `dabai_dcw2.launch`。节点**自动拉起**相机，
  若 roscore/相机已在跑则直接订阅。
- ROS master：两节点 `main()` 在 `rospy.init_node()` **之前**调用 `ensure_master()`——没 master 自动拉起
  roscore（否则 init_node 直接抛异常）；退出时回收本封装拉起的进程，不影响已存在的节点。
- 云台：只走 `gimbal_server.py` 的 `/gun/aim /gun/fire /gun/home` 服务，**绝不直写 `/dev/gun`**。

## 2. 上机步骤

### 2.1 一键启动两个主节点

```bash
roslaunch raicom2026 detect.launch
```
会启动：gimbal_server + usb_cam(webcam) + webcam_person_gun + orbbec_mine_antitank。

### 2.2 触发各任务（另开终端）

```bash
# 人物区 (Ⅰ→A, Ⅱ→B, Ⅲ→C, Ⅳ→D)
rostopic pub -1 /person_detect std_msgs/String "A"
# 雷区 (Ⅱ→A, Ⅲ→B)
rostopic pub -1 /mine_detect std_msgs/String "A"
# 反坦克盘 (Ⅳ 走廊)
rostopic pub -1 /antitank_check std_msgs/Empty "{}"
```

### 2.3 看结果

```bash
rostopic echo /person_detect_status     # 如 "A区发现2个敌军、1个友军和0个人质"
rostopic echo /mine_detect_status       # 如 "A雷区未排雷数量1个,已经排雷数量0个"
rostopic echo /vision/anti_tank_event   # "DETECTED ... D=1.20m conf=0.88" / "NONE"
ls data/evidence/                       # R_*.jpg (人物), M_A_red_conf0.8*.jpg (雷区), AT_*.jpg (反坦克)
cat data/reports/report_person.txt data/reports/report_mine.txt
```

> 雷区证据图命名 `M_<区>_<色>_conf<最高置信>.jpg`，比赛要求识别结果必须留图存档。

### 2.4 合并终版报告（比赛结束前）

```bash
rosrun raicom2026 assemble_report.py       # → data/reports/report.txt
rosrun raicom2026 assemble_report.py --print   # 只打印检查
```

## 3. 标定（必须！否则打靶会系统性脱靶）

未标定前代码用默认值：`ppd=12.11 px/度`、`s_h=+1`、`s_v=-1`、`t0=80°`、`tilt_offset=0`（不补偿弹道）。

用 `scripts/calibrate.py` 的 `ppd` 子命令标定后，把结果写进 **`param/params.yaml`**（节点启动时自动读取）：

```yaml
# param/params.yaml (节点读取的键)
ppd_h: 12.11            # 水平 px/度
ppd_v: 12.11            # 垂直 px/度 (应与 ppd_h 相近)
s_h: 1.0                # 水平方向符号因子 (+pan 目标往哪边移, 标定确定)
s_v: -1                 # ⚠️ 垂直方向符号因子 (见下方 s_v 标定步骤)
calibrated: false       # ⚠️ 标定确认门: 完成 ppd/s_v/弹道标定并验证后改 true,
                        # 否则节点禁止开火(仅计数), 防止脱靶/误指友军
t0: 80.0                # 各区俯仰基准 (方案建议 78-82)
tilt_step: 10.0         # 两档俯仰差
tilt_offset_a0: 0.0     # 弹道垂直补偿 a0
tilt_offset_a1: 0.0     # 弹道垂直补偿 a1 (tilt_offset = a0 + a1/距离)
target_h_m: 0.30        # 目标贴纸物理高度(m), 框高反推距离用
focal_px: 610.0         # orbbec 焦距(px), 反坦克盘测距用
```

### 3.1 `s_v` 方向标定（**必做，填反 = 永远打不中**）

`s_v` 决定"云台仰/俯"在图像里的像素方向，直接影响瞄准闭环：

- 调高 `/gun/aim` 的 `tilt` 指令角度时，看目标贴纸在画面中是**向下移**（`v` 增大）→ `s_v = -1`；
  若**向上移**（`v` 减小）→ `s_v = +1`。
- 填反了：瞄准闭环微调会**发散**，云台越调越偏，永远触发不了 `FIRE`（安全但不射中，白丢 10 分）。
- 步骤：`/gun/aim` 对准一个人物 → `tilt` 从 90 调到 100 → 记录目标中心 `v` 是变大还是变小，按上式填 `param/params.yaml`。
- 注意：`ppd` 标定只给 px/度数值，**不**决定符号；两个都必须标定。

> 其余标定方法见方案 §3.2 与 `calibrate.py` 帮助；`tilt_offset` 需要在 0.8/1.5/2.0m 实测弹道落点。
> **没标定前不要打靶**（`--dryrun` 只扫数不射击）。

## 5. 自主导航编排（`nav_competition.py`，8/10 新增）

> 替代 `1205/main/nav_competition.py`（旧版直写 `/dev/gun` 违 C5、发 "start" 旧契约、
> 航点硬编码）。本节点**只**走 move_base action + `/person_detect|/mine_detect` 触发契约，
> 云台/打靶/避障全在其他节点。

### 5.1 职责（状态机）
```
BOOT 等 /map + 连 move_base + 发 AMCL 初始位姿
  → NAV 巡航到各站 (move_base action, 每段超时+重试)
  → TASK 触发人物/雷区并等字节精确状态串 (超时重发一次)
  → … → REPORT 调 report.assemble_report 合并 report.txt (恰好 6 行)
```
- 每段导航超时 `nav_timeout_s`、全局预算 `global_budget_s`（默认 280s，超时跳过剩余站直接收尾）
- **Ⅳ 走廊**（航点 `iv: true`）：move_base 被反坦克盘堵死时，等陈旧避障云消失
  （`iv_stall_wait_s`）→ 沿垂直到达段方向横向偏移 `iv_lateral_offset_m` 发临时目标绕行；
  绕不过就放弃该区交通（宁丢 D 交通不碰盘）。
- 状态话题 `/nav_competition/state`（如 `t=42.5s NAV:B_pos`），实时看跑到哪了。

### 5.2 配置（实机 8/10 必做：重测航点）

航点/初始位姿全在 `param/nav_competition.yaml`，**只改配置不改代码**：
- `amcl_initial_pose`：比赛起点，实测后写死（否则 AMCL 可能不收敛）
- `course`：各停靠站 `x y yaw_deg`（占位为旧地图坐标，**必须在新图 competition_map 上重测**）
- 改完用以下命令自查（不连 master，纯校验）：
  ```bash
  rosrun raicom2026 nav_competition.py --print-course
  ```

### 5.3 验证（bench，不下车）
- 启动后看 `/nav_competition/state`：`BOOT → NAV:A_pos → TASK:人物A → NAV:B_pos → … → REPORT → DONE`
- `rostopic echo /nav_competition/state` 实时看每站到达与耗时
- 各站到达后检测节点自己上报/打靶，nav 只负责触发与等状态（人物实测一区 ≈17s，状态要 ≥20s 窗口）

**触发/状态话题均为 std_msgs/String**；nav 只订阅 `/person_detect_status /mine_detect_status`，
读取字节精确报告串做确认（首字符=区名）。

## 6. 子系统 C：视觉避障（导航常驻节点，不触发式）

> 对应方案 §5；节点 `scripts/visual_mine_avoidance.py`，随导航一起跑，不需要触发话题。
> 职责：导航期间持续检测雷区盘(mine.onnx) + 反坦克盘(antitank.onnx)，确认后展开球面点云发布
> `/visual_mine/obstacles`，由 move_base costmap 的 `visual_mine` 观察源注入 obstacle_layer 自动绕行。

### 6.1 启动（比赛用主入口，已含 driver + 静态 TF + move_base 注入）

```bash
roslaunch raicom2026 nav_competition_2026.launch use_rviz:=false
```

启动后**必须自检**（注入失败 = 点云发了但 costmap 不认，等于没避障）：

```bash
rosparam get /move_base/local_costmap/observation_sources   # 必须输出 "scan visual_mine"
rosparam get /move_base/global_costmap/observation_sources  # 同上
rosrun tf tf_echo base_link camera_link                     # 有平移输出即静态TF正常
rostopic hz /visual_mine/obstacles                          # ≈4-5Hz (本机CPU封顶)
```

- 节点每 ~3s 自检，未注入会 loud logwarn 提示"必须用 nav_competition_2026.launch"。
- 模型缺失 → **logfatal + exit(1)**（不会带病跑成"空云"）。
- bench 只测避障（不导航）可用 `roslaunch raicom2026 visual_mine_avoidance.launch use_rviz:=true`。

### 6.2 bench 标定相机外参（**必做**，否则云位置偏、绕行偏）

```bash
roslaunch raicom2026 visual_mine_avoidance.launch use_rviz:=true
# RViz Fixed Frame = base_footprint
# 车静止，贴纸/真盘放相机前 0.4~0.9m
# 看 /visual_mine/markers 红色球体是否压在贴纸中心
```

- 未标定默认外参：`cam_x=0.15 cam_y=0 cam_z=0.25`，roll/pitch/yaw=0（车头前方俯视）。
- 偏移 → 改 launch 的 `cam_*` 参数（`cam_yaw/cam_pitch/cam_roll` 用度）直至球体压住贴纸，写回
  `nav_competition_2026.launch` 与 `visual_mine_avoidance.launch` **两处**。
- 通过门槛：球心与真值的水平误差 <0.15m。标定通过后再上整车。

### 6.3 调参速查（`param/visual_mine_avoidance.yaml`）

| 键 | 默认 | 说明 |
|---|---|---|
| `~mine_radius` / `~at_radius` | 0.12 / 0.15 | 盘半径(m)，决定障碍物点云直径与匹配半径 |
| `~mine_conf` / `~at_conf` | 0.5 | 置信阈值；误报多可提 0.55~0.6 |
| `~at_infer_interval` | 3 | 反坦克盘每隔几 tick 推理一次（省 CPU） |
| `~tracker_min_hits` / `~max_miss` | 2 / 8 | 时序确认帧数 / 丢帧数 |
| `~max_range` | 1.0 | 有效测距上限(m)，忽略远处误报 |
| `~cloud_n_pts` | 20 | 每盘球面点数 |
| `~obs_source_key` | `/move_base/local_costmap/observation_sources` | 注入自检键 |

### 6.4 预期指标（本机 4 核实测量得）

- `/visual_mine/obstacles` 实际 ≈4-5Hz（mine.onnx 单次 ~0.20s，CPU 封顶；理论 10Hz 上限）。
- **静态盘 + observation_persistence=2.0 → obstacle 层连续标记，低帧率可接受**；盘移走 ~2s 自然消失，不堵回程。
- 想提速：先调大 `~at_infer_interval`；`~intra_op_num_threads=4` 只快 5%，不值得。

## 7. 降级行为（节点自带）

| 故障 | 行为 |
|---|---|
| 云台服务不可用 | `webcam_person_gun` 仅计数不转云台不打靶（报所见即所得） |
| webcam 无帧 | 人物报 0 + 不打靶 |
| orbbec 无帧 | 雷区/反坦克报空 |
| 模型文件缺失 | 节点启动即报 fatal 退出（不会带病运行） |
| **未确认标定** | `param/params.yaml` 缺 `calibrated: true` → logfatal + **禁开火**（仅计数）。标定完成改 true 后重启 |
| 相机自动拉起失败 | 已存在的相机直接订阅；无帧持续降级 |
| 反坦克点云 | 默认**关闭**（`~publish_obstacle_cloud:=false`）。⚠️ 单点/只发一次/无清除，仅当静态 TF 已标定并验证过才可开 |
| 避障 rgb/depth 无帧 | `visual_mine_avoidance` 不发云（空云保 hz），不崩；持续无帧 = 相机没起/断线 |
| 避障模型缺失 | `visual_mine_avoidance` 启动即 logfatal + exit(1)（**不带病跑空云**） |
| 避障未注入 costmap | 节点每 3s 自检 `observation_sources`，缺 `visual_mine` 会 loud logwarn（说明没用对 launch） |
| 避障 depth 编码未知 | 跳过 3D 化，仅 2D 检测帧持续走 tracker；已知 16UC1/32FC1 正常 |
