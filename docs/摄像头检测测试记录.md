# 双相机（单目 + 深度）检测与出图测试记录

> 日期：2026-08-07
> 平台：Ubuntu 18.04，Linux 5.4.0，x86_64
> 目标：检测设备上连接的单目相机与深度相机能否打开，并抓取、展示画面

---

## 1. 任务背景

设备上连接了 **两个相机**：一个单目相机、一个深度相机。需要：
1. 确认两个相机能否被系统识别、能否打开；
2. 抓取两路画面并展示给用户。

## 2. 硬件与软件环境

### 2.1 USB 拓扑（测试后梳理）

```
USB Host (0000:00:14.0)
└─ 1-4   USB2.0 HUB (214b:7250)
   ├─ 1-4.2   USB Serial (CH340)
   ├─ 1-4.3   Integrated Webcam (Realtek 0bda:3031)   ← 板载摄像头
   └─ 1-4.4   USB 2.0 Hub (1a40:0101)                  ← DaBai 内部 hub
      ├─ 1-4.4.1  ORBBEC Depth Sensor  (2bc5:06a0)      ← 深度相机
      └─ 1-4.4.3  Orbbec DaBai DCW2 RGB Camera (2bc5:0561)  ← 单目 RGB 相机
```

- **Orbbec DaBai DCW2**（SN: `AUI964300EK`）是一个 RGB-D 一体相机，通过内部 hub 暴露两个 USB 端点：RGB 模块（2bc5:0561，Sonix 芯片，UVC 设备）与深度模块（2bc5:06a0，OpenNI/Astra 协议）。用户所说的「单目相机」= RGB 模块，「深度相机」= 深度模块。
- **Integrated Webcam**（Realtek 0bda:3031）是另一路板载 UVC 摄像头。

### 2.2 软件环境

| 组件 | 版本/位置 |
|------|-----------|
| Python | conda env `yolov8`，Python 3.8，OpenCV 4.13.0 |
| Orbbec SDK | libOrbbecSDK 1.8.3（`~/本 ws 内 orbbec_camera / lslidar 等驱动包/src/OrbbecSDK_ROS/SDK/lib/x64`） |

| 图形显示 | DISPLAY=:0（mowen 用户桌面），`eog` 图片查看器 |

## 3. 总体测试思路

```
识别硬件 ──→ 检查系统识别状态 ──→ 尝试打开出图 ──→ 故障定位 ──→ 修复 ──→ 展示
   │              │                    │
 lsusb           v4l2节点              每个相机独立测试
 dmesg           sysfs属性
```

**核心原则**：
1. 先搞清楚物理上有什么（USB 拓扑、厂商 ID），再动手打开；
2. 每个相机分别测试，记录「能否打开 / 能否出图 / 图像内容是否有效」三个层次；
3. 遇到打不开时，逐层排查：USB 枚举 → 驱动绑定 → 视频节点 → 实际取流；
4. 软件能修的先修，修不了的就定位到硬件层并给出操作建议。

## 4. 详细测试过程

### 4.1 设备识别

**命令：**
```bash
lsusb                              # 列出 USB 设备
ls -l /dev/video*                  # 视频节点
v4l2-ctl --list-devices            # V4L2 设备
dmesg | grep -iE 'usb|uvc|camera'  # 内核日志
```

**发现：**
- 系统存在 3 个摄像头设备（见 2.1 拓扑）；
- 当时只有 `/dev/video0`（Integrated Webcam）有视频节点；
- dmesg 显示 Orbbec RGB 相机重新插拔时报 `No valid video chain found`，未生成节点。

### 4.2 Integrated Webcam（Realtek）测试

**方法：** 用 `v4l2-ctl` 和 OpenCV 分别尝试取流，多分辨率多次尝试。

```bash
v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=3    # 报 Protocol error
python3 -c "import cv2; cap=cv2.VideoCapture('/dev/video0', cv2.CAP_V4L2); ok,f=cap.read(); ..."
```

**结果：**
- `v4l2-ctl` 直接取流报 `VIDIOC_STREAMON: failed: Protocol error`；
- OpenCV 打开成功，但**间歇性出图**（多次尝试中 640x480 / 320x240 / 160x120 时好时坏）；
- 抓到的帧亮度均值约 101、灰度标准差约 43，说明**能拍到有效画面**；
- **结论：该摄像头能用但不稳定**（疑似接触/带宽问题），且它不是本次任务的重点（Orbbec 才是）。

### 4.3 Orbbec 相机测试

#### 4.3.1 遇到的第一个障碍：`/dev/video` 节点缺失

Orbbec RGB 相机的 UVC 链路失败，没有视频节点，因此无法直接用 OpenCV 打开。

#### 4.3.2 尝试 pip 安装 pyorbbecsdk（失败）

```bash
pip install pyorbbecsdk    # 装上了，但导入失败
```

**教训：** 装到的 `pyorbbecsdk-1.3.2` 是 **macOS (darwin) + Python 3.11** 的二进制，而系统是 **Linux + Python 3.8**，平台不匹配。该版本旧、无 Linux wheel。
**转向方案：** 直接用系统里已有的 **libOrbbecSDK 1.8.3**（x64 Linux），写 C++ 工具调取。

#### 4.3.3 编写 SDK 抓图工具 `grab_orbbec.cpp`

**设计要点：**
- 用 `ob::Context` 枚举设备 → 选第一个 DaBai；
- 打印每个 sensor（COLOR / DEPTH / IR）的全部 profile，便于确认可用格式；
- 按偏好顺序选择 profile：COLOR 优先 `RGB888 → MJPG → YUYV`；DEPTH 优先 `Y16 → Y11`；
- 启动 `Pipeline`，`waitForFrames` 抓帧，手动把帧写成标准格式：
  - RGB888 → PPM；
  - MJPG → 原字节直接存 `.jpg`（MJPG 帧本身就是完整 JPEG）；
  - YUYV → 手动转 RGB888；
  - DEPTH（Y16/Y11，SDK 默认解成 uint16）→ 16bit PGM + 归一化 8bit PGM；
- 编译：`g++ -I<SDK include> -L<SDK lib> -lOrbbecSDK -Wl,-rpath,<lib>`

> 关键 API 确认（SDK 1.8 与网上资料略有差异）：
> - `FrameSet` 取帧用的是 `colorFrame() / depthFrame() / irFrame()`（不是 `getColorFrame()`）；
> - `connectionType()` 返回 `const char*`，无 `OB_CONNECTION_USB2_0` 枚举；
> - 头文件入口是 `#include <libobsensor/ObSensor.hpp>`（C++），不是 `ObSensor.h`（C）。

#### 4.3.4 第一次运行：SDK 找到设备但 USB 传输出错

- SDK **成功枚举**到设备：`DaBai DCW2, PID=0x06a0, SN=AUI964300EK, USB2.0`；
- DEPTH / IR 的 profile 齐全，但 **COLOR profile 为空**；
- 大量 `Failed to submit asynch I/O transfer`、`Get usb core type failed`；
- 深度一帧都抓不到。

**逐层排查定位：**
```bash
cat /sys/bus/usb/devices/1-4.4.1/bConfigurationValue   # 空！设备未配置
cat /sys/bus/usb/devices/1-4.4.1/speed                 # 12 (full-speed!)
dmesg | grep -iE 'usb 1-4.4|error'
```
关键日志：
```
[启动时]   usb 1-4.4.1: new HIGH-speed USB device      # 正常应 480Mbps
[重新插拔后] usb 1-4.4.1: new FULL-speed USB device     # 降到 12Mbps
[重新插拔后] usb 1-4.4.1: can't set config #1, error -32  # EPIPE, 配置被设备 stall
```

**根因结论：USB 物理链路降速。** 整个 DaBai（含内部 hub）从 high-speed 降到 full-speed，深度传感器因此无法完成 SET_CONFIGURATION，RGB 的 UVC 链路也随之失败。属于典型的线缆/接口接触不良或供电不足。

### 4.4 软件修复尝试（全部无效）

| 方法 | 说明 | 结果 |
|------|------|------|
| `USBDEVFS_RESET`（写 usbreset 工具） | 对 `/dev/bus/usb/001/0xx` 发 ioctl 复位 | 复位成功，但仍 full-speed，速度不重新协商 |
| 复位内部 hub | hub 节点无对应设备文件 | 无法操作 |
| `authorized` 开关 | `/sys/bus/usb/devices/.../authorized` 仅 root 可写 | 无权限（sudo 需密码） |
| `uvcvideo` 重新绑定 | 需 root | 无权限 |

**结论：软件层面无法恢复，必须物理重新插拔。**

### 4.5 重新插拔后（修复成功）

**结果验证：**
```bash
cat /sys/bus/usb/devices/1-4.4.1/speed        # 480 (high-speed 恢复)
cat /sys/bus/usb/devices/1-4.4.1/bConfigurationValue  # 1 (配置成功)
v4l2-ctl --list-devices                       # 出现 Orbbec DaBai /dev/video2 video3
```

**SDK 再次抓图（一次全成功）：**
```
取得 COLOR 帧: 640x480 RGB888 dataSize=921600
取得 DEPTH 帧: 640x400 Y16 valueScale=1  min=0 max=1007
取得 IR 帧:    640x400 Y16
结果: color=OK depth=OK ir=OK
```

**深度数据有效性分析（Python/OpenCV）：**
- 有效像素 76%（0-4000mm 内）；
- 测距范围 **123 ~ 1007mm**，均值 **266mm**；
- 说明深度相机拍到了 0.5m 内的真实物体，**工作正常**。

### 4.6 图像生成与展示

用 OpenCV 把原始帧转成可视化图片并拼图：

| 文件 | 内容 |
|------|------|
| `orbbec_rgb.png / .jpg` | 单目相机 640x480 彩色画面 |
| `orbbec_depth_jet.png` | 深度图伪彩色（越近越红） |
| `orbbec_depth_gray.png` | 深度图灰度 |
| `orbbec_depth_raw.pgm` | 原始 16bit 深度数据 |
| `orbbec_ir.png` | 红外图 |
| `orbbec_montage.png` | 四宫格总览（RGB / Depth / IR / Webcam） |

**展示方式：**
```bash
DISPLAY=:0 nohup eog ~/cam_results/orbbec_montage.png &
```
在用户桌面 `:0` 用 eog 打开拼图窗口，并把结果复制到 `~/cam_results/` 持久保存。

## 5. 结论

| 相机 | 能否打开 | 能否出图 | 说明 |
|------|---------|---------|------|
| **单目 RGB**（Orbbec DaBai DCW2 RGB，2bc5:0561） | ✅ | ✅ | 640x480 RGB888 彩色帧正常 |
| **深度相机**（ORBBEC Depth，2bc5:06a0） | ✅ | ✅ | 640x400 深度帧正常，测距 0~1m 有效 |
| IR 红外流 | ✅ | ✅ | 随深度相机提供 |
| Integrated Webcam（Realtek） | ⚠️ | ⚠️ | 能打开但不稳定，疑似接触/带宽问题 |

**关键教训：**
1. **USB 物理层问题优先确认**：遇到深度相机「枚举成功但取不了流」，先看 `dmesg` 里有没有降速（high-speed → full-speed）和 `error -32 (EPIPE)`，这类问题**软件修复不了，只能重新插拔/换线/换口**。
2. **SDK 平台匹配**：pyorbbecsdk 老版本只有 macOS wheel，直接 pip 装会在 Linux 上导入失败；优先用系统已有的 C++ libOrbbecSDK。
3. **video2 节点会因 SDK 使用 libusb 而消失**：SDK 抓图后可能 detach 掉 uvcvideo，导致 `/dev/video2` 消失。这不影响 SDK/ROS 取流，但要用 OpenCV 直接开 RGB 时需重新插拔恢复节点。

### 6.2 抓图工具 `grab_orbbec.cpp` 核心逻辑

```cpp
#include <libobsensor/ObSensor.hpp>
using namespace ob;

auto ctx = std::make_shared<Context>();
auto dev = ctx->queryDeviceList()->getDevice(0);   // DaBai DCW2
auto pipe = std::make_shared<Pipeline>(dev);
auto config = std::make_shared<Config>();
config->enableStream(colorProfile);                 // RGB888/MJPG/YUYV 择优
config->enableStream(depthProfile);                 // Y16/Y11
pipe->start(config);
auto fs = pipe->waitForFrames(200);
auto color = fs->colorFrame();                      // 注意：SDK 1.8 用 colorFrame()
auto depth = fs->depthFrame();                      //       不是 getColorFrame()
// 帧数据: color->data() / depth->data() (uint16)
// 尺寸:   color->width() / color->height()
```

### 6.3 USB 复位工具 `usbreset.c` 核心逻辑

```c
#include <linux/usbdevice_fs.h>
int fd = open("/dev/bus/usb/001/024", O_RDWR);   // 设备节点(全体可写)
ioctl(fd, USBDEVFS_RESET, 0);                     // 触发设备复位
```
