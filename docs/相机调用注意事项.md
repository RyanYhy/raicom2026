## 1. 硬件概览

设备上共 **两个实体相机**：

| 实体相机 | 内部端点 | VID:PID | 输出画面 | 调用方式 |
|---|---|---|---|---|
| Orbbec DaBai DCW2（RGB-D 一体） | RGB 模块 | `2bc5:0561` | 彩色 RGB | Orbbec SDK（或 UVC）|
| 同上 | 深度模块 | `2bc5:06a0` | 深度 | **只能** Orbbec SDK |
| Integrated Webcam（板载） | — | `0bda:3031` | 彩色 RGB | UVC（`/dev/video0`）|

USB 拓扑：

```
USB Host (0000:00:14.0)
└─ 1-4  USB2.0 HUB (214b:7250)
   ├─ 1-4.2 CH340 串口
   ├─ 1-4.3 Integrated Webcam (0bda:3031)
   └─ 1-4.4 DaBai 内部 hub (1a40:0101)
      ├─ 1-4.4.1 ORBBEC Depth (2bc5:06a0)
      └─ 1-4.4.3 Orbbec RGB (2bc5:0561)
```

> ⚠️ **关键认知**：DaBai 的 RGB 模块与深度模块虽然 `lsusb` 里是两个端点，但属于**同一个物理相机**。深度模块走 OpenNI/Astra 私有协议，**不能用 V4L2/OpenCV 直接打开，必须用 Orbbec SDK**。

## 2. 启动前健康检查

```bash
lsusb | grep -E '2bc5|0bda'      # 两个相机是否在位
cat /sys/bus/usb/devices/1-4.4.1/speed                # 深度模块，必须是 480
cat /sys/bus/usb/devices/1-4.4.1/bConfigurationValue  # 必须是 1
dmesg | grep -iE '2bc5|can.t set config'              # 有无降速/配置失败记录
```

**判断标准**：深度模块 `1-4.4.1` 的 `speed=480` 且 `bConfigurationValue=1` 才算正常可调用。

## 3. 最常见故障：USB 降速 / 不枚举（重点 ⭐）

### 症状
1. `lsusb` 里完全没有 `2bc5` 设备 —— 常见于**系统重启后**，设备压根没被控制器看到。
2. 设备在，但 `speed=12`（full-speed），且 `bConfigurationValue` 为空 —— 深度模块配置失败。
3. dmesg 出现 `can't set config #1, error -32`（EPIPE，配置被设备 stall）。

### 根因
DaBai 的 USB 链路**存在接触不良 / 供电不足**的物理问题，历史多次复现，属物理层故障。

### 为什么软件修不了

| 尝试 | 结果 |
|---|---|
| `usbreset`（USBDEVFS_RESET） | 设备节点 `root:root` 不可写，无权限 |
| `/sys/bus/usb/devices/.../authorized` 开关 | 仅 root 可写 |
| 重新绑定 `uvcvideo` 驱动 | 需 root |
| `sudo` | 需要密码，无免密配置 |

### 唯一解决办法：物理重新插拔

1. **完全拔出** DaBai 的 USB（不是只动线），**等 5 秒**。
2. 插回时确保**插到底、无松动**。
3. 若插回仍是 full-speed，**换个 USB 口**。
4. 插回后用第 2 节命令确认 `speed=480`、`config=1`。

> 实测：插拔不一定一次成功——本次故障中第一次插回落在 full-speed，第二次才到高速。**多试几次，以第 2 节判断标准为准**，不要凭 lsusb 能看到就认为正常。

## 4. Orbbec DaBai 调用要点（SDK）

- **版本**：libOrbbecSDK **1.8.3**（x64 Linux），位于 `~/本 ws 内 orbbec_camera / lslidar 等驱动包/src/OrbbecSDK_ROS/SDK/`。
- **语言**：用 **C++**。**不要用 pyorbbecsdk** —— 1.3.2 只有 macOS + Python 3.11 的 wheel，Linux 装不上、导入即失败。
- **头文件**：`#include <libobsensor/ObSensor.hpp>`（C++ 入口，不是 `ObSensor.h`）。
- **关键 API**：
  - 取帧用 `frameSet->colorFrame() / depthFrame() / irFrame()`（**不是** `getColorFrame()`）。
  - `connectionType()` 返回 `const char*`，无 `OB_CONNECTION_USB2_0` 枚举。
- **深度格式**：深度模块 profile 只有 **Y11/Y12**，SDK 会自动解包成 **Y16（uint16）**，数值单位 mm（`getValueScale()` 一般为 1）。
- **分辨率/帧率**：RGB 640x480 RGB888、深度 640x400，双路 **15fps** 在 USB2 下实测稳定。USB2 带宽有限，不建议更高帧率。
- **深度可视化**：0~2m 范围做 jet 伪彩色、**越近越红**（与文档惯例一致）；无效/超量程显示黑色。

### profile 选择的一个坑（重要）

选帧率时**不要用 `abs()`** —— 如果不 `#include <cstdlib>`，`abs` 会被解析成恒等函数（分数恒为负数），导致"选最接近 15fps"永远选中最低帧率。要用手动绝对值：

```cpp
int df = vp->fps() - targetFps;
if (df < 0) df = -df;          // 不要用 abs()
int score = df * 2 + (vp->fps() > targetFps ? 1 : 0);
```

### 副作用：/dev/video 节点会消失

SDK 用 libusb 访问 RGB 时会 **detach 掉 uvcvideo**，导致 `/dev/video2/video3` 节点消失。这**不影响 SDK 取流**（RGB 也走 SDK），但若要用 OpenCV 直接开 RGB，需重新插拔恢复节点。

## 5. 板载 Webcam 调用要点

- **设备**：`/dev/video0`（`/dev/video1` 是配套节点）。
- **编码**：用 **MJPG**（YUYV 带宽高、更易失败）。
- **分辨率——最重要的坑**：**`640x480` 取不到流**（实测 0/15 帧，UVC probe 失败）。这是历史文档里"不稳定/间歇性出图"的**真正原因**。
- **可用分辨率**：**848x480、1280x720、320x240 等均 100% 稳定**（60/60 帧实测）。
- **推荐**：`848x480 MJPG`（画质与带宽的平衡；webcam 与 DaBai 共享同一 USB hub 带宽）。
- **OpenCV 打开方式**：

```python
import cv2
cap = cv2.VideoCapture('/dev/video0', cv2.CAP_V4L2)
cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*'MJPG'))
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 848)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 480)
cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)      # 降低延迟
ok, frame = cap.read()                   # 失败时 ok=False，需容错重试
```

## 8. FAQ

- **Q：重启后 `lsusb` 看不到 2bc5？**
  A：物理重插，见第 3 节。属接触问题，软件无法恢复。
- **Q：深度取不到帧？**
  A：先查 `speed` 是否 480、`config` 是否 1。大概率 USB 降速，重新插拔。
- **Q：要用 OpenCV 直接开 DaBai 的 RGB？**
  A：需要 `/dev/video` 节点存在。SDK 用过后节点会消失，重新插拔恢复；或用 SDK 取 RGB。
- **Q：要接入 ROS？**
  A：用 `~/本 ws 内 orbbec_camera / lslidar 等驱动包/src/OrbbecSDK_ROS/launch/dabai_dcw2.launch`。
- **Q：webcam 640x480 打不开，是坏了？**
  A：不是。640x480 在此设备上固件/链路不支持，换 848x480 或 1280x720。
