## 1. 这套建图链路是什么

```
┌────────────────────── bringup_robot.launch（只引用 robot_bringup，与导航完全一致）┐
│  lslidar_driver ── /scan (laser_link, 0.15~100m, 屏蔽90-270°)                │
│  wit IMU ── /imu (base_link)                                                 │
│  base_controller ── 订阅 /cmd_vel，驱动底盘                                    │
│  odometry_publisher ── odom_raw ── robot_localization EKF ── /odom (odom→base_footprint) │
│  static TF: base_footprint→laser_link (0.1,0,0.05,yaw=π), base_footprint→base_link 恒等 │
└──────────────────────────────────────────────────────────────────────────────┘
        │ /scan                │ /odom
        ▼                      ▼
┌────────────── cartographer_node（my_car.lua）──────────────┐
│  纯激光 2D + EKF 里程计；输出 map→odom TF + 子图             │
└──────────────────────┬────────────────────────────────────┘
                       │ 子图
                       ▼
┌── cartographer_occupancy_grid_node（resolution=0.05）──┐
│  输出 /map（nav_msgs/OccupancyGrid）                     │
└──────────────────────┬───────────────────────────────────┘
                       ▼
      map_saver → data/maps/competition_map.pgm/.yaml
```

关键点：**建图用的 bringup 与比赛导航完全一致**，所以建出来的地图坐标系（odom→base_footprint→laser_link）和比赛时 AMCL 读到的一致，不用再换算。

## 3. 上机步骤

### 3.1 启动建图

```bash
# 终端1：一键启动（bringup + cartographer + rviz）
roslaunch raicom2026 test/launch 内建图 launch（已归档）
```

等约 5~10s，rviz 里出现 `map` 固定坐标系，`/map` 和 `/scan` 有数据显示。

> 无显示器/不想开 rviz：`roslaunch raicom2026 test/launch 内建图 launch（已归档） rviz:=false`
>
> 排查顺序（logs 都在启动终端）：
> 1. 雷达没数据 → 检查 `/dev/lslidar`（ttyACM0）是否插好；`rostopic hz /scan`
> 2. cartographer 报 "Couldn't get transform ... odom" → EKF 还没出 /odom，等几秒；`rostopic hz /odom`
> 3. /map 没更新 → 看 cartographer_occupancy_grid_node 是否活着；`rostopic hz /map`

### 3.2 开车建图（键盘遥操作必须单独开终端）

```bash
# 终端2：键盘遥操作（roslaunch 起的节点没有 stdin, 所以单独 rosrun）
rosrun raicom2026 teleop_keyboard.py
```

| 键 | 动作 |
|---|---|
| W / S | 前进 / 后退 |
| A / D | 左移 / 右移（横移） |
| Q / E | 逆时针 / 顺时针原地转 |
| X / Space | 停车 |
| + / − | 调速度倍率（0.1~3.0，建图建议 ≤1.0 慢速） |

**安全：松开按键约 1.5s 自动停车**（防止终端卡死/误触跑飞）。

### 3.3 建图走线要点（决定地图质量）

1. **慢速**（倍率 0.5~1.0），Mecanum 横移别猛，激光扫描 5~10Hz，快转/快移会糊。
2. 沿场地四周跑一圈，再绕中间障碍物转一圈，**每条边都进雷达视野（< 6m）**。
3. 多转几圈回到起点附近 → 触发**回环**（回环是提高全局一致性的关键，rviz 里能看到回环约束/子图优化）。
4. 停在一个空旷开阔处结束。

### 3.4 保存地图

```bash
# 终端3（在 test/launch 内建图 launch（已归档） 运行期间）：先 X 停车，等 /map 稳定，再执行
rosrun raicom2026 save_map.sh
```

输出 `data/maps/competition_map.pgm/.yaml`。可用 `rosrun map_server map_server data/maps/competition_map.yaml` + rviz 直接检查。

## 4. 地图质量检查清单

- [ ] `.pgm` 里场地边界闭合、无大块黑影/噪点
- [ ] 角落、门洞、柱子轮廓清晰，没有「重影/双墙」
- [ ] `.yaml` 的 `resolution: 0.05`、`origin` 合理、`image` 指向 `.pgm`
- [ ] 雷区/击倒区等关键位置在图上能对上真实坐标（8/10 要用它定航点）

若图有重影：回环没建好（走得不够循环），或速度太快。调参优先改 `config/cartographer/my_car.lua`（见下）。

## 5. 可选：pbstream 高精度存档（不用也行）

`/map` 是实时占用格快照，偶有边缘抖动。cartographer 还支持存完整轨迹状态 `.pbstream`，后续可离线重刷地图：

```bash
# 建图结束停在原地时（终端2）
rosservice call /write_state "{filename: '$PWD/data/maps/competition_state.pbstream', include_unfinished_submaps: true}"
# 需要时再用 pbstream 导出地图
rosrun cartographer_ros cartographer_pbstream_to_ros_map -map_filestem data/maps/competition_pbstream data/maps/competition_state.pbstream
```

比赛导航只需要 `.pgm/.yaml`，所以第 3.4 步的 map_saver 已足够。

## 6. 想调参？改 `config/cartographer/my_car.lua`（包内可写）

改完**直接重启 `test/launch 内建图 launch（已归档）`** 生效。括号里是**当前生效值**（没写进 my_car.lua 的 = 用默认值，见 `trajectory_builder_2d.lua` / `pose_graph.lua`，已在 `config/cartographer/` 外、由编译内置目录解析）。

### 6.0 先分清「精度不够」的原因（大部分是开车/回环问题，不是参数）

- 日志 `constraint_builder_2d: N computations resulted in M additional constraints`：**M=0 说明一条回环都没闭合**，全局必然漂 → 先绕场走一圈回到起点附近，别急着调参。
- 雷达 FOV 只有 180°（robot_bringup `truncated_mode` 90-270，**只读**），视野先天受限，回环比 360° 雷达难。
- 慢速（teleop 倍率 ≤1.0），别长时间原地打转。

### 6.1 精度调参优先级（★ = 最值得先动）

| 优先级 | 参数 | 当前生效值 | 建议 | 效果/风险 |
|---|---|---|---|---|
| ★1 | `POSE_GRAPH.constraint_builder.min_score` | 0.65 | **0.50~0.55** | 回环接受门槛降低 → 全局一致性大幅提升；回环出不来时首选 |
| ★2 | `TRAJECTORY_BUILDER_2D.submaps.resolution` | 0.05（默认） | **0.025** | 匹配网格细一倍 → 局部精度最直接；内存×4、CPU↑（7.5G 够） |
| ★3 | `TRAJECTORY_BUILDER_2D.real_time_correlative_scan_matcher.linear_search_window` | 0.1 | 0.2~0.5 | 防打滑/跟丢，容忍位移偏差；CPU 略增 |
| ★4 | `TRAJECTORY_BUILDER_2D.voxel_filter_size` | 0.025 | 0.01~0.02 | 保留更多激光点匹配；CPU/内存增 |
| ★5 | `TRAJECTORY_BUILDER_2D.motion_filter.max_distance_meters` | 0.2（默认） | 0.1 | 插帧更密、重叠更多；CPU 增 |
| | `TRAJECTORY_BUILDER_2D.motion_filter.max_angle_radians` | math.rad(1.)（默认） | math.rad(0.5) | 同上 |
| ★6 | `POSE_GRAPH.optimization_problem.odometry_translation_weight` | 1e5 | 1e4~1e3 | 打滑时降低里程计在全局优化里的权重，更信激光回环；别降太狠会抖 |
| | `POSE_GRAPH.optimization_problem.odometry_rotation_weight` | 1e5 | 1e4~1e3 | 同上 |
| 7 | `TRAJECTORY_BUILDER_2D.submaps.num_range_data` | 90（默认） | 60~70 | 子图更小、回环更频繁；可试 |
| — | `POSE_GRAPH.optimization_problem.huber_scale` | 1e2 | **别动** | 对异常值钝感的鲁棒核，数据不干净时的保护 |
| — | `POSE_GRAPH.optimize_every_n_nodes` | 3 | **别动** | 已从默认 90 压到 3，全局优化已非常频繁 |
| — | `TRAJECTORY_BUILDER_2D.use_online_correlative_scan_matching` | true | **别动** | 已打开（默认 false） |

### 6.2 诊断开关（不影响精度，帮判断）

```lua
POSE_GRAPH.optimization_problem.log_solver_summary = true   -- 打印每次全局优化的 solver 收敛残差
```

### 6.3 基础参数（保持不动）

- `TRAJECTORY_BUILDER_2D.max_range = 12.0`（雷达有效 12m，N10_P 硬件 100m）
- `TRAJECTORY_BUILDER_2D.missing_data_ray_length = 5.0`（空旷处填充距离，太小图会裂）
- `TRAJECTORY_BUILDER_2D.min_range = 0.1`
- `use_imu_data = false`（IMU 由 EKF 融合进 /odom，cartographer 直接用里程计，车上验证过的配置）

### 6.4 验证

同一条路线改前/改后各跑一遍，对比：
1. 日志 `constraint_builder_2d` 的 **M additional constraints 是否 >0**（回环闭合）
2. rviz /map 有没有双墙/重影
3. 存图后 `.pgm` 边界闭合、边角清晰

## 8. 常见故障排查

### 8.1 cartographer 崩溃 `map_by_time.h: Check failed: data.time > std::prev(...)`（已修）

**现象**：cartographer_node 启动约 1~2 秒后 FATAL 崩溃，日志两处时间戳**完全相等**。

**原因**：cartographer 要求 odometry 时间戳**严格递增**（`MapByTime::Append` 的 `CHECK_GT`）。EKF/底盘在启动瞬间可能发出重复或倒退时间戳的 `/odom`，撞上即崩。上游在只读包（robot_bringup），改不了。

**解法（已内置）**：`test/launch 内建图 launch（已归档）` 里 `odom_cleaner.py` 把 `/odom` 过滤成严格递增的 `/odom_clean`，cartographer 改读 `/odom_clean`。重复/乱序帧直接丢弃，对 SLAM 精度无实质影响。

**验证**：
```bash
rostopic info /odom                    # 确认只有一个发布者(EKF); 若 >1 个, 先找到并关掉多余的
rostopic hz /odom_clean                # 应有 ~20Hz
rostopic echo -n1 /odom_clean/header/stamp   # 连续看几条, 时间戳应单调递增
```

### 8.2 启动初期 `Lookup would require extrapolation ... from [laser_link] to [base_link]`

TF 缓冲还没填满时的正常启动噪音，等 1~2 秒消失即可，不是错误。

### 8.3 `WARN: unrecognized 'param' tag in <include> tag`

来自 robot_bringup 自带 launch（lslidar include 里塞了 `<param>`），roslaunch 每次都会打，`queue_size` 不生效但无害，忽略。

### 8.4 启动终端必须用你平时的 shell

test/launch 内建图 launch（已归档） 依赖 cartographer_ws / 本 ws 内 orbbec_camera / lslidar 等驱动包 的包（`~/.bashrc` 已 source）。换个干净 shell（只 source melodic + 1raicom_ws）会报 `package cartographer_ros not found`。
