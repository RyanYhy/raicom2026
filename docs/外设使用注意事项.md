## 3. 端口占用冲突（重点 ⚠️）

### 3.1 舵机/水弹枪 与 Orbbec：**已分开，不再共用** ✅

- 历史问题：枪与相机曾共用 1-4.4（二选一）。
- **2026-08-08 已解决**：枪改插 **1-4.3**，Orbbec 独占 **1-4.4**，两者物理口分离，**可同时在线**。
- `gun.rules` 已从 `KERNELS=="1-4.4:1.0"` 更新为 **`KERNELS=="1-4.3:1.0"`** → 生成 `/dev/gun`（验证：`/dev/gun → ttyUSB2`）。
- ⚠️ **不要再把枪插回 1-4.4**（那是 Orbbec 的口）；也不要让 Orbbec 占 1-4.3（会抢枪的规则）。

### 3.2 arm 与 carserial：共用 1-6 口（潜在冲突）

- `arm.rules` 和 `carserial.rules` 都绑定 `KERNELS=="1-6:1.0"` → `/dev/arm` 和 `/dev/carserial` **指向同一个 ttyUSB0**。
- 当前 1-6 上是底盘控制器。ultraArm 机械臂未接。
- 若以后插 ultraArm，会与底盘冲突（同一端口无法同时连两个设备）。需给机械臂换口并改规则。

### 3.3 命名不一致

- `joy_bringup.py` 里写的是 `/dev/usb_gun`，但 udev 规则生成的是 `/dev/gun`。**`/dev/usb_gun` 不存在**。接云台手柄控制前需统一（改成 `/dev/gun` 或补规则）。

## 4. 各外设使用要点

### 4.1 底盘（`/dev/carserial` @115200）

- 发送帧（`base_controller.py`）：`AA BB 0A 12 02 vx_lo vx_hi vy_lo vy_hi vz_lo vz_hi 校验`（12 字节，小端有符号 short，单位 mm/s）
- 控制器持续上报 12 字节状态帧：`aa bb 0a 0a 00 00 00 00 00 00 00 14`（实测正常）
- 驱动：`robot_bringup/ 或 robot_navigation/scripts/base_controller.py`；launch 见 `bringup_robot.launch`
- 帧头 `AA BB` 与枪协议同族，注意别串口

### 4.2 IMU（WitMotion `/dev/imu` @9600）

- **必须先发解锁指令**才有数据流：`FF AA 69 88 B5`
- 数据帧（11 字节）：`55 <类型> + 8 字节数据 + 校验`
  - 0x51 加速度 / 0x52 角速度 / 0x53 角度（roll/pitch/yaw ×0.01°）/ 0x54 四元数
  - 校验 = 前 10 字节（含 0x55）求和 mod 256
- 实测：解锁后 10+ 帧通过，静止角度值合理
- 驱动：`wit_multi_ros.py`（port=/dev/imu, baud=9600）

### 4.3 激光雷达（镭神 N10_P `/dev/lslidar` @460800）

- **波特率必须是 460800**（N10_P）；M10 系列是 500000/921600，别混
- 数据包：`A5 5A` 同步头 + **108 字节**固定长包，末字节 = CRC8（前 107 字节求和 mod 256）
- N10/N10_P/L10 **无需发送启动指令**（M10 需要）
- 驱动：`lslidar_driver`（`lidar_name=N10_P`, `serial_port=/dev/lslidar`）
- 实测：55 同步头、54/55 CRC 通过（丢 1 帧属正常，驱动自动跳过）
- launch 里已屏蔽 90°~270° 角度段（`truncated_mode=1`，disable_min=90 disable_max=270）

### 4.4 遥控手柄（XING WEI 2.4G）

- 以 **HID 键盘+鼠标**模式枚举（1-1），**没有 `/dev/input/js*` 节点** → `pygame.joystick` 可能识别不到
- `joy_bringup.py` / `joy_bringup_ros.py` 依赖手柄，但当前 bringup 里已被注释
- 若比赛需手柄遥控，需先确认 pygame 能读到该设备，或改用手柄厂商驱动
- 另注意 `joy_bringup.py` 还引用了不存在的 `/dev/usb_gun`

### 4.5 舵机 ×2 + 水弹枪（`/dev/gun` @115200，**端口 1-4.3**）

- 协议帧：`AA BB <ID> <数据> 0D 0A`（6 字节，`gun_server.py` / `duoji1.py`）
  - 舵机1：`AA BB 01 <角度> 0D 0A`（角度字节，0x5A=90°、0x69=105°；安全范围 70~110）
  - 舵机2：`AA BB 02 <角度> 0D 0A`
  - 水弹枪开火：`AA BB 03 01 0D 0A`；停止：`AA BB 03 00 0D 0A`
- **控制板无主动上报**（只响应指令），验证靠物理观察
- 水弹枪点射：发开火后短暂延时再发停止（实测 **0.05s 点射有效**）；避免长时间连续发射（有散热冷却需求，代码里配了 3 秒冷却期）
- 复验（2026-08-08）：舵机 90°→100°→90° 正常；**0.05s 点射正常发射**
- **接线注意**：枪的 CH340 枚举为 full-speed（正常特性）；Type-C 必须用**数据线**（充电线无数据线芯会完全无法枚举）。本次经历：双头 Type-C 和 Type-C→USB-A 充电线都不稳定/不识别，换数据线后正常
- ⚠️ **当前枪必须插 1-4.3**，否则 `gun.rules` 不触发、无 `/dev/gun`（见 §3.1 / FAQ）

### 4.6 Orbbec DaBai 相机（详见相机文档）

- 端口：**1-4.4**（Terminus hub 下 1-4.4.1 深度 / 1-4.4.3 RGB）
- 必须 `speed=480` 且 `bConfigurationValue=1`，否则需物理重插（复验时 480/1 均正常）
- 深度走 OpenNI 私有协议，**必须用 Orbbec SDK**；SDK 会 detach uvcvideo

#### 4.6.1 相机外参标定（安装位姿，2026-08-15 实测）

| 参数 | 值 | 含义 |
|---|---|---|
| `cam_x` | 0.18 m | 相机中心在 base_link 原点（底盘地面中心）**前方 18cm** |
| `cam_y` | **−0.12 m** | **偏右 12cm**（y 左正右负）—— 点云偏左 12cm 的根源，必须带负号 |
| `cam_z` | 0.20 m | 镜头中心离地 20cm |
| `cam_pitch` / `cam_roll` / `cam_yaw` | 0 / 0 / 0 | 水平正前装，无俯仰无偏航（标定后 by≈0 证明无 yaw）|

- **基准**：base_link 原点 = 底盘几何中心在地面的投影（`base_footprint→base_link` 单位阵，z=0 贴地），坐标 x 前 / y 左 / z 上。
- **落地位置**：`competition/launch/nav_multi_visual_mine.launch` 的 `cam_x/cam_y/cam_z/cam_*` arg 默认值（detector 的 `camera_frame=camera_color_optical_frame`，静态 TF 发 `base_link→camera_link`，驱动续发到 optical）。
- **标定方法**（换支架/重装后重做）：雷放正前方 0.5m 正中贴地 → 跑 `python2 /home/mowen/check_cloud_pos.py`（点云环心→base_link 帧）→ 期望 `(0.50, 0.00, 0.01)`；实测减理论 = 误差，`新cam = 旧cam − 误差`。
- ⚠️ 点云 z 恒为 0.01 是代码写死（`_make_cloud_points`），**不能用来验证 cam_z**；cam_z 用卷尺量镜头离地。

### 4.7 板载 Webcam（端口 1-4.1）

- **640x480 取不到流**（UVC probe 失败）；用 **848x480 MJPG** 稳定（复验取流成功）

## 5. 健康检查命令

```bash
# 1. 全部外设 USB 在位（应看到 7 个 USB 设备 + 相机 hub）
lsusb | grep -E '1a86|0bda|2bc5|1915|1a40'

# 2. 各设备符号链接（8 项）
ls -l /dev/carserial /dev/imu /dev/lslidar /dev/gun /dev/arm

# 3. 雷达波特率验证（460800 下应有 A5 5A 同步头 + CRC 通过）
python3 -c "
import serial
s=serial.Serial('/dev/lslidar',460800,timeout=1)
d=s.read(6000)
syncs=[i for i in range(len(d)-1) if d[i]==0xA5 and d[i+1]==0x5A]
ok=sum(1 for i in syncs if i+108<=len(d) and (sum(d[i:i+107])&0xff)==d[i+107])
print('同步头:%d CRC通过:%d'%(len(syncs),ok))
"

# 4. IMU 验证（发解锁指令后应有 0x51-0x54 帧）
python3 -c "
import serial,time
s=serial.Serial('/dev/imu',9600,timeout=1)
s.write(bytes([0xFF,0xAA,0x69,0x88,0xB5])); time.sleep(0.3)
d=s.read(120)
print('IMU帧数:',sum(1 for i in range(len(d)-10) if d[i]==0x55 and d[i+1] in (0x51,0x52,0x53,0x54)))
"

# 5. 底盘状态帧
timeout 1 python3 -c "
import serial
s=serial.Serial('/dev/carserial',115200,timeout=0.5)
print('底盘帧:',s.read(12).hex(' '))
"

# 6. Orbbec 480M/config 检查（必须都是 480 / 1）
for d in /sys/bus/usb/devices/1-4.4*; do
  [ -e "$d/idVendor" ] && [ "$(cat $d/idVendor)" = "2bc5" ] && \
  echo "$(basename $d) speed=$(cat $d/speed) config=$(cat $d/bConfigurationValue 2>/dev/null)"
done
```

## 7. FAQ

- **Q：枪插上没反应（lsusb 看不到）？**
  A：① 确认是**数据线**不是充电线；② Type-C 用力插到底；③ **确认插在 1-4.3**（1-4.4 是 Orbbec 的口）。
- **Q：枪插在 1-4.3 但 `/dev/gun` 不存在？**
  A：检查 `gun.rules` 是否绑定 `KERNELS=="1-4.3:1.0"`；改规则后需 `sudo udevadm control --reload-rules && sudo udevadm trigger --subsystem-match=tty`。
- **Q：雷达没数据？**
  A：查波特率是否 460800；`/dev/lslidar` 是否指向 ttyACM0。
- **Q：IMU 没数据？**
  A：要先发解锁指令 `FF AA 69 88 B5`。
- **Q：Orbbec 深度取不到帧 / 没枚举？**
  A：查 `speed` 是否 480、`config` 是否 1（§5 命令 6）。大概率 USB 降速，**物理重插**（可能要试 1-2 次），详见相机文档。
- **Q：`/dev/usb_gun` 打不开？**
  A：规则生成的是 `/dev/gun`。`joy_bringup.py` 里的 `/dev/usb_gun` 需改成 `/dev/gun` 或补一条规则。
- **Q：手柄 pygame 读不到？**
  A：设备是 HID 键盘/鼠标模式，无 `/dev/input/js*`。需确认 pygame 兼容或改方案。
- **Q：为什么换了 USB 口节点就没了？**
  A：所有串口规则都是**按端口（KERNELS==）绑定**，换物理口即失效。改口后要同步改对应 `.rules` 并 reload/trigger。
